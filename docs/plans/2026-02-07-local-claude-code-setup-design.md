# Local Claude Code with Qwen3-Coder-Next-FP8 via vLLM + LiteLLM

## Goal

Single setup script that turns a GPU server (with CUDA installed) into a local Claude Code backend using:
- **Model**: Qwen/Qwen3-Coder-Next-FP8 (80B MoE, 3B active params, FP8)
- **Inference**: vLLM (>= 0.15.0) serving OpenAI-compatible API
- **Bridge**: LiteLLM proxy translating Anthropic API → OpenAI API
- **Package manager**: uv

## Architecture

```
Claude Code ──(Anthropic API)──► LiteLLM :4000 ──(OpenAI API)──► vLLM :8000 ──► GPU
```

## Target Hardware

- Single RTX 6000 PRO (96GB VRAM)
- Tensor parallel size: 1 (configurable)
- Max context: 32K tokens (configurable)

## Repository Structure

```
local-code/
├── setup.sh              # Single entry point (start/stop)
├── litellm-config.yaml   # Generated by setup.sh
├── .env.example          # Example env vars for Claude Code
└── README.md             # Usage instructions
```

## setup.sh Design

### CLI Parameters

| Flag | Default | Description |
|------|---------|-------------|
| `--max-model-len` | 32768 | vLLM max context length |
| `--tensor-parallel-size` | 1 | Number of GPUs for tensor parallelism |
| `--vllm-port` | 8000 | vLLM serving port |
| `--litellm-port` | 4000 | LiteLLM proxy port |
| `--gpu-memory-utilization` | 0.95 | vLLM GPU memory fraction |
| `stop` | - | Subcommand: stop all services |

### Phase 1: Preflight

- Verify `nvidia-smi` works, print GPU info
- Verify CUDA available
- Verify `uv` installed (exit with install instructions if missing)
- Parse CLI arguments

### Phase 2: Environment

- `uv venv .venv`
- `uv pip install vllm>=0.15.0 litellm[proxy]`
- Generate `litellm-config.yaml`

### Phase 3: Start Services

1. Start vLLM in background:
   ```
   vllm serve Qwen/Qwen3-Coder-Next-FP8 \
     --port $VLLM_PORT \
     --tensor-parallel-size $TP_SIZE \
     --max-model-len $MAX_MODEL_LEN \
     --gpu-memory-utilization $GPU_MEM \
     --enable-auto-tool-choice \
     --tool-call-parser qwen3_coder
   ```
   - PID saved to `.vllm.pid`
   - Logs to `logs/vllm.log`

2. Poll `http://localhost:$VLLM_PORT/health` until ready (timeout: 10 min for model download)

3. Start LiteLLM in background:
   ```
   litellm --config litellm-config.yaml --port $LITELLM_PORT
   ```
   - PID saved to `.litellm.pid`
   - Logs to `logs/litellm.log`

4. Poll `http://localhost:$LITELLM_PORT/health` until ready

### Phase 4: Print Instructions

Output the env vars needed for Claude Code:
```
export ANTHROPIC_BASE_URL=http://localhost:4000
export ANTHROPIC_AUTH_TOKEN=sk-local
claude
```

### Stop Mode

`setup.sh stop` reads PID files, kills processes, cleans up.

## LiteLLM Config

```yaml
model_list:
  - model_name: "claude-*"
    litellm_params:
      model: hosted_vllm/Qwen/Qwen3-Coder-Next-FP8
      api_base: http://localhost:8000/v1
      api_key: "not-needed"
    model_info:
      max_tokens: 32768
      max_input_tokens: 24576
      max_output_tokens: 8192

litellm_settings:
  drop_params: true
  request_timeout: 600
  modify_params: true

general_settings:
  master_key: sk-local
  disable_key_check: false
```

- `claude-*` wildcard catches all model names Claude Code sends
- `hosted_vllm/` prefix routes to vLLM's OpenAI-compatible endpoint
- `drop_params: true` drops Anthropic-specific params silently
- `request_timeout: 600` allows long code generations
